# Film Review RAG

This project is a sophisticated Retrieval-Augmented Generation (RAG) system designed to answer questions about a private knowledge base of movie reviews. It leverages a powerful Large Language Model (LLM) but constrains it to only use verified information from the provided documents, ensuring factual, trustworthy, and verifiable responses.

The system is engineered for a dual-environment setup, allowing for seamless development on a local system using Docker and deployment to a production environment on Streamlit Cloud.

---

## ✨ Key Features

* **Dual-Environment Ready**: Full support for both local development (with Docker) and cloud deployment (Streamlit Cloud) from a single, unified codebase.
* **Interactive Chat Interface**: A clean and professional UI for users to ask questions about movie reviews.
* **Evidence-Based Answers**: Every answer generated by the AI is based on specific text chunks retrieved from the knowledge base, which are displayed to the user for full transparency.
* **No Hallucinations**: The system is engineered to avoid making up facts, demonstrated by a 100% precision score in our evaluations.
* **Multi-Format Data Ingestion**: A robust data pipeline that can load, clean, and process data from various formats including `.csv`, `.xlsx`, `.pdf`, `.json`, and `.txt`.
* **Built-in Performance Evaluation**: A sophisticated, in-app evaluation module to quantitatively measure the system's accuracy, precision, recall, and $F_1$ score against a ground-truth dataset.

## 🏗️ Project Architecture & Workflow

The project follows a classic, multi-stage RAG pipeline, separating data processing (ingestion) from the live application (inference).

[Raw Data Files]      ▶️      [1. Data Ingestion]      ▶️      [2. Vector DB]        ▶️      [3. RAG Application]
(.csv, .pdf, .txt...)         (loading.py, embed.py)         (weavite.py)      (Weaviate Docker/Cloud)      (ui.py)
│                             │                            │                       │                        │
└─(Extract & Chunk)─▶─(Generate Embeddings)─▶─(Upload Chunks)─▶─(Retrieve Context)─▶─(Generate Answer)─▶─[User]

**Data Ingestion Pipeline:**

* `loading.py`: Reads raw data from the `review-data/` folder, cleans it, and uses an intelligent chunking strategy to break it into meaningful pieces.
* `embed.py`: Takes the text chunks and uses the `all-MiniLM-L6-v2` model to create a vector embedding for each, capturing its semantic meaning.
* `weavite.py`: Uploads the chunks and their corresponding embeddings into our Weaviate vector database.

**Vector Database (Weaviate):**
Acts as the external "brain" for the application. The system is configured to use a local Docker container for development and Weaviate Cloud for production.

**RAG Application (`ui.py`):**

1.  The user asks a question via the Streamlit interface.
2.  The UI embeds the question and queries Weaviate to retrieve the most relevant text chunks.
3.  The chunks and the question are then sent to the `llama-3.3-70b-versatile` model via the Groq API.
4.  The final, grounded answer is displayed to the user along with the source evidence.

## 🚀 Environment Setup

This project supports two distinct environments. Follow the steps for the environment you wish to use.

### 1. Local System Setup (using Docker)

This setup is ideal for development, testing, and running the ingestion pipeline.

**Prerequisites**
* Python 3.8+
* Docker and Docker Compose installed and running.

**Steps**

1.  **Clone the Repository:**
    ```bash
    git clone [https://your-repository-url.git](https://your-repository-url.git)
    cd your-project-folder
    ```

2.  **Set Up Weaviate with Docker:**
    Create a `docker-compose.yml` file in your root directory:
    ```yaml
    ---
    version: '3.4'
    services:
      weaviate:
        image: semitechnologies/weaviate:latest
        ports:
          - "8080:8080"
        restart: on-failure:0
        environment:
          QUERY_DEFAULTS_LIMIT: 25
          AUTHENTICATION_ANONYMOUS_ACCESS_ENABLED: 'true'
          PERSISTENCE_DATA_PATH: '/var/lib/weaviate'
          DEFAULT_VECTORIZER_MODULE: 'none'
          ENABLE_MODULES: ''
          CLUSTER_HOSTNAME: 'node1'
    ```
    Start the Weaviate container in the background:
    ```bash
    docker-compose up -d
    ```

3.  **Set Up Local Credentials:**
    Create a file named `.env` in the root of the project. For the local setup, we point to our Docker container.
    ```bash
    # .env for LOCAL DOCKER setup
    GROQ_API_KEY="your_groq_api_key_here"
    WEAVIATE_CLUSTER_URL="http://localhost:8080"
    WEAVIATE_API_KEY="dummy-key" # API key is not required for local anonymous access
    ```

4.  **Install Python Dependencies:**
    It is highly recommended to use a virtual environment.
    ```bash
    python -m venv venv
    source venv/bin/activate  # On macOS/Linux
    # venv\Scripts\activate  # On Windows

    pip install -r requirements.txt
    ```

5.  **Run the Ingestion Pipeline:**
    This populates your local Weaviate Docker container with your data.
    ```bash
    python loading.py
    python embed.py
    python weavite.py
    ```

6.  **Launch the Application:**
    ```bash
    streamlit run ui.py
    ```

### 2. Streamlit Cloud Setup (Production)

This setup is for deploying your application to the web.

**Prerequisites**
* A GitHub account and a repository for your project.
* A Streamlit Community Cloud account.
* A Weaviate Cloud instance.

**Steps**

1.  **Populate Weaviate Cloud:**
    You must run the ingestion pipeline configured to target your cloud instance.
    * Temporarily update your local `.env` file to point to your Weaviate Cloud credentials.
    * Run the ingestion pipeline: `python loading.py`, `python embed.py`, `python weavite.py`.
    * **Important**: Change your `.env` file back to the local Docker settings afterward.

2.  **Push Code to GitHub:**
    Ensure your `ui.py`, `requirements.txt`, `critic.png`, and all other necessary files (except `.env`!) are pushed to your GitHub repository.

3.  **Configure `.gitignore`:**
    Make sure your `.gitignore` file contains `.env` to prevent your local secrets from being uploaded.
    ```
    # Ignore environment files
    .env

    # Ignore Python virtual environment
    venv/

    # Ignore Python cache files
    __pycache__/
    ```

4.  **Set Up Streamlit Cloud Secrets:**
    * In your Streamlit app's settings, go to the "Secrets" section.
    * Add your production credentials. These will be automatically used by the deployed app.
    ```toml
    # Streamlit Cloud secrets [secrets.toml]
    GROQ_API_KEY = "your_real_groq_api_key_gsk_..."
    WEAVIATE_CLUSTER_URL = "[https://your-weaviate-cluster-url.weaviate.network](https://your-weaviate-cluster-url.weaviate.network)"
    WEAVIATE_API_KEY = "your_real_weaviate_cloud_api_key"
    ```

5.  **Deploy:** Connect your GitHub repository to Streamlit Cloud and launch the application. The `ui.py` script is designed to automatically use the cloud secrets when deployed.
